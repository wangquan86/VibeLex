# VibeLex V3.2 发布说明

V3.2 新增 `POST /api/v3/recommendations`，调用方可提交剧情、台词、事件或聊天上下文，获得去重并按相关性排序的已发布词条。推荐使用一次 embedding、一次语义 kNN 和一次 BM25 查询，并通过加权 RRF 融合。

本版本将 Elasticsearch 与 embedding 从 V2 识别模块提升为共享 `search` 模块。索引严格保持一个 active 义项一份文档，并且只投影当前已发布词条；V1、V2 识别、V3 推荐、普通查询和后台管理均不返回内部归档记录。

数据库迁移 `V12__remove_redundant_safety_policy_flags.sql` 删除 `detect_enabled`、`generate_enabled` 和 `recommend_enabled` 及对应约束、索引。V2 响应和管理查询不再返回这三个字段。

作为对既有词条生命周期的小幅优化，人工录入、文件导入和网站爬取统一按已发布主词形、有效变体和有效候选判重，重复内容不再允许保存，归一化词形锁继续保护并发准入。正式词条撤回时不再创建人工候选，而是将原候选恢复为编辑中并保留原来源（包括来源类型、导入运行和来源地址）；后续人工编辑也不能改写这些来源字段。重新发布固定更新原正式词条，不能因编辑词形而静默切换目标。`disabled` 正式状态废弃，下线统一等同于撤回至候选。

`archived` 仅作为数据库内部的历史审计状态，不出现在正式词条页面、业务查询、识别、推荐、统计或 Elasticsearch 索引中。撤回会写入 `meme_revisions` 审计版本并删除共享索引文档。既有的唯一归档异常通过 `deploy/maintenance/v3.2-entry-lifecycle-cleanup.sql` 一次性整理；该脚本带固定数据断言，只执行一次，不纳入 Flyway 迁移链。

作为对 V3.1 导入链路的补丁优化，文件导入和网站爬取统一在 AI 调用前按词条判重。CHIME 和波普词典在 AI 语义丰富连续 3 次失败后，改用来源基础内容创建候选；Buzzword 和热梗百科仍保持最终失败且不创建候选。管理页面将逐条记录的 `imported` 状态统一显示为“已进入候选”。V3.0、V3.1 历史文档不做追溯修改。

导入吞吐进一步优化：文件导入和网站爬取 Worker 的调度间隔由 3 秒缩短为 500 毫秒，后台调度池默认扩展为 5 个线程，使文件导入、网站爬取和索引同步可以并行执行；词条判重由三次数据库查询合并为一次，并通过按归一化词条加锁保护并发下的二次判重与候选创建，避免生成重复候选。

网站爬取 Worker 按来源拆分为波普词典和热梗百科两条独立串行通道：两个来源可以并行处理，各来源内部仍保持一次处理一条记录，避免全局按记录 ID 领取导致后启动来源长期处于待处理状态。

热梗百科在页面材料包含起源说明时，将对应热梗百科原页面保存为起源引用；没有起源说明时不生成引用。dev 环境中既有且尚未人工编辑的热梗候选已通过一次性数据修复补齐原页面链接，不纳入 Flyway 迁移链。

波普词典 AI 丰富校验进一步收敛：复合词条按可用词形匹配例句，并在匹配前统一繁简体和英文大小写；例句数量不足、重复、过长或未包含有效词形改为质量软失败，保留可用的起源和引用并标记人工复核，不再触发整条记录重试。结构错误、未知字段、联网搜索或引用真实性问题仍按硬失败重试；连续 3 次硬失败后使用来源原始内容进入候选，并在爬取记录中保留最后一次 AI 失败摘要。

网站爬取管理页在点击“立即爬取”后立即进入轮询和准备状态，不再等待后端启动请求完成才刷新；爬取记录按最近更新时间倒序显示。Responses API 返回非 2xx 状态时，后台错误摘要会记录经过脱敏和截断的错误代码、类型、参数、消息及上游请求 ID，便于定位 HTTP 400 等上游拒绝原因。

V3 推荐新增独立 CPU Reranker 重排序：语义与词法结果经 RRF 融合并按词条去重后，依据请求的 `max_results` 将实际待返回候选一次性提交给 Reranker，最终按模型分数降序返回，分数相同时保留 RRF 顺序。`relevance_score` 改为 Reranker 分数。重排序默认开启，可通过 `VIBELEX_RERANKER_ENABLED=false` 关闭；服务超时、非 2xx 或响应结构异常时自动回退原 RRF 排序，推荐接口不被阻断。该功能不改变 Elasticsearch 索引结构，也不需要数据库迁移或全量重建。

推荐默认关闭。必须先执行共享索引全量重建、切换 `vibelex_sense_current`、完成 V2 回归，再设置 `VIBELEX_RECOMMENDATION_V3_ENABLED=true`。
