# VibeLex 数据来源与采集治理规范

**项目名称：** VibeLex  
**产品版本：** V1.0  
**文档修订：** 1.1  
**状态：** 设计规范

---

## 1. 目的与范围

本规范定义 VibeLex 如何发现、接入、使用和留存网络语言相关的数据来源。

VibeLex 是经过整理和审核的语言知识库，不是未经审核的网络内容聚合器。数据采集的目标是发现候选表达、核验词义与语境、观察趋势，并为已发布词条提供可追溯的证据；不以沉淀大量原始网络内容为目标。

本规范适用于人工录入、批量导入、用户投稿、合作数据、公开网页、公开趋势页面、公开数据集和经授权的 API 数据。

---

## 2. 基本原则

1. **最小化采集与留存**：只获取完成词条发现、核验和趋势判断所必需的信息；默认保存结构化结论、必要短摘录、来源链接和观察时间，不批量长期保存原始帖文、评论或用户资料。
2. **来源可追溯**：已发布词条的重要释义、起源、趋势和风险结论应能关联到具体证据。
3. **先候选、后发布**：自动化只可产生候选、去重、聚类和趋势预警；词义、风险等级、起源叙述和公开发布须经人工审核。
4. **合规优先**：公开可见不等于可批量抓取、长期存储、训练或再分发。接入前应确认适用的服务条款、robots 规则、API/授权范围、版权及隐私要求。
5. **语境优先**：单个来源或单条内容通常不足以代表通用用法。记录时应保留语言、圈层、地区（如适用）和观察时间。
6. **可撤回与可复核**：来源失效、授权变化、证据不足或结论过期时，应能停止使用、标记失效并触发词条复核。

## 3. 数据来源分层

| 来源层 | 主要用途 | 典型输入 | 默认处理方式 |
|---|---|---|---|
| `internal` | 编辑观察、产品反馈、模型发现 | 编辑录入、内部候选清单 | 进入候选池，补充外部或可核验依据后发布 |
| `dataset` | 样本、评测、内部语料 | 已获许可的数据集、合作方数据 | 按许可范围使用；记录版本、许可和保留期限 |
| `dictionary` | 词条发现与释义参考 | 公开词典、术语库 | 作为参考证据，不直接复制受保护内容 |
| `trend` | 热度与传播观察 | 公开热榜、话题页、搜索趋势、授权 API | 保存聚合指标、链接和时间；不默认保留原始内容 |
| `explanation` | 释义、背景和起源核验 | 创作者公开说明、媒体报道、公开说明页 | 提炼结论与必要短摘录，保留链接和时间 |
| `community` | 垂类表达发现与用法观察 | 游戏、二次元、职场等公开社区 | 用于发现或补充语境；避免以孤立内容概括通用含义 |
| `overseas` | 外来梗与跨语言表达补充 | 海外社区、词典、趋势页 | 明确原语言、目标语言和本地化用法 |

来源层描述的是来源的功能，不代表可信度等级；同一来源可以承担多个功能。

## 4. 来源、原始内容与证据

三者需明确区分：

- **来源（Source）**：可持续访问或复用的渠道，例如某个获得授权的 API、公开趋势页或合作数据集。
- **原始内容（Raw content）**：来源中的帖文、评论、视频标题、指标记录等原始材料。原则上不作为 V1 的长期核心存储对象。
- **证据（Evidence）**：从来源于某一时刻观察到、用于支撑一个具体词条结论的最小记录。

现有 `meme_evidence` 是词条证据的承载表，记录来源名称、链接、来源层、证据用途、摘要、观察时间、置信度和状态。它服务于词条审核与可追溯性，不能替代来源接入配置。

管理页面中的三个相近概念必须区分：

- **数据导入来源**：候选最初来自哪个已登记数据源；V1 仅为 CHIME、Buzzword 或人工录入。它用于导入追溯，不展示为词条起源链接。
- **词条起源**：词条为何出现、如何传播的业务说明及其参考链接，由编辑维护。
- **AI变体参考来源**：一次联网生成 AI 变体时返回的词条级参考链接组；它不与单个变体一一对应，也不替代人工审核。

当来源数量、更新任务或授权要求增加时，应引入 `data_sources`，集中维护来源元数据；`meme_evidence` 通过 `source_id`（或等价关联）引用该来源，同时保留当时的名称和链接快照，以避免来源配置变化影响历史审计。

## 5. 来源接入登记

任何可持续采集或批量导入的来源，在启用前应登记至少以下信息：

| 信息 | 说明 |
|---|---|
| 来源名称与类型 | 平台、数据集、合作方、编辑渠道或 API |
| 访问方式 | 人工观察、公开页面、官方 API、文件导入或合作交付 |
| 允许用途 | 候选发现、词义核验、趋势计算、评测等 |
| 授权与限制 | 许可依据、服务条款、robots/API 限制、再分发限制 |
| 可采集字段 | 明确可保存的字段；区分链接、聚合指标、短摘录和原文 |
| 更新策略 | 更新频率、限流策略、失败处理和停止条件 |
| 留存策略 | 保留期限、删除/脱敏规则、是否允许持久化原文 |
| 责任信息 | 来源负责人、审核责任人和最近复核时间 |
| 可信度与适用范围 | 适合支撑的结论类型、语言/地区/圈层覆盖及已知偏差 |

未完成登记或无法确认使用边界的来源，不应进入自动化采集流程；必要时只能作为人工临时参考，且不得批量留存。

## 6. 候选发现与发布流程

```text
已登记来源 / 人工录入 / 用户投稿
                ↓
         候选词池（未发布）
                ↓
      去重、归一化、聚类、趋势预警
                ↓
   编辑补充释义、语境、风险与来源证据
                ↓
             人工审核
                ↓
       发布词条并保留审计版本
                ↓
       定期复核、失效处理或归档
```

候选池中的记录不得因“已被采集”而被视为事实或公开词条。V1 候选状态统一为 `editing`（编辑中）、`pending_review`（审核中）、`returned`（已退回）和 `published`（已发布）；审核退回后允许修改并重新提交，不使用候选“不采纳”或候选草稿状态。

建议的发布最低要求：

- 有明确的规范词形、语言及至少一个可解释的义项；
- 释义和适用语境已由编辑确认；
- 有与结论匹配的证据；争议性、敏感性或起源类结论宜采用两类独立来源交叉核验；
- 已完成风险分级与必要的展示、生成、推荐限制；
- 已记录审核人与审核时间。

---

## 7. 自动化边界

允许自动化完成：

- 从已登记、允许自动接入的来源提取候选词或聚合趋势信号；
- 词形归一化、去重、频次统计、异常检测和候选聚类；
- 根据规则或模型生成待审核的释义建议、变体建议和风险提示；
- 发现来源不可访问、授权到期或趋势异常时创建复核任务。

不得仅凭自动化结果完成：

- 自动发布词条、释义、起源结论或风险标签；
- 将模型推断当作来源证据；
- 绕过来源限制采集内容，或批量保存超出获准范围的原文和个人信息；
- 因单一高频内容而认定某用法具有普遍性。

---

## 8. 隐私、版权与内容安全

- 不将用户名、账号标识、联系方式、精确位置、私信等个人信息作为词条数据保存；确有必要的审核材料应脱敏并设置访问控制与期限。
- 原始文本、截图、音视频及其转写受来源规则和版权约束。除非许可明确支持，不作为可公开导出或再分发的数据资产。
- 引用应以必要、短小和可核验为原则；以链接和编辑摘要替代大段复制。
- 涉及攻击性、歧视性、性、未成年人、违法或其他高风险表达时，采集和审核应遵循更严格的访问、展示与留存限制。
- 用户投稿应声明投稿者拥有提交权限，并避免接收不必要的个人信息；投稿本身仍须审核和补证据。

---

## 9. 失效、复核与审计

下列情况应触发来源或词条复核：

- 来源链接失效、内容不可访问或来源规则发生变化；
- 授权、服务条款、API 权限或 robots 规则变化；
- 词条热度、用法或风险显著变化；
- 证据被证伪、存在重要争议，或审核发现引用不当；
- 来源长期未更新、质量下降或偏差显著。

处理结果可包括停用来源、停止任务、将证据标记为 `invalid` 或 `removed`、下调置信度、将词条转为待复核、修订后发布或归档。所有影响已发布词条的操作应写入版本与审核记录。

---

## 10. V1 实施范围

V1 优先建设以下能力：

1. 人工录入与 CHIME、Buzzword 数据文件手工导入的候选池；
2. `meme_evidence` 驱动的来源、链接、摘要、时间和置信度记录；
3. 审核后台与词条版本记录；
4. CHIME、Buzzword 的来源登记或等价配置，记录许可证、文件版本/哈希、用途和字段范围；
5. 同步分批导入、运行记录和人工失败重试。

V1 不引入爬虫、定时采集、消息队列、缓存中间件、全量社交内容仓库或自动发布系统。其他数据集、公开趋势页/API、独立的 `data_sources`、采集任务调度和数据血缘均在现有手工导入闭环验证后再评估。

### 11.1 接入优先级

```text
V1 已接入：CHIME、Buzzword（手工导入，用于词条候选与释义参考）

V1 同时支持管理台人工录入候选。人工录入不是外部数据集导入来源，而是候选创建方式。
已放弃接入：zh-meme-sft-8k（对话 SFT 数据不适合直接映射为词条候选）  
后续评估：MOD（小样本探索）
后续评估：MNBVC（先评估适配性）
可手工接入：Buzzword（已获授权；使用独立 Importer）
```

### 11.2 各来源接入前的共同检查项

以下检查项用于 CHIME 之外的后续来源；CHIME V1 手工导入使用 `source_import_runs` 中的默认值并允许操作者覆盖。

1. 固化访问日期、版本/提交号、许可证文本和数据卡快照；
2. 核验许可证是否覆盖数据文件本身，以及其上游原始内容是否有额外限制；
3. 明确 VibeLex 的使用范围：候选发现、人工参考、模型评测、内部处理或可公开再分发；
4. 对导入字段做映射和最小化处理，去除不需要的个人信息、原始长文本和多媒体内容；
5. 以小批量导入验证重复率、质量、风险分布与人工审核成本后，再决定是否扩大接入。
